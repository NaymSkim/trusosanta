# Тайный Трусосанта 🩲

Самостоятельная регистрация без аккаунтов: имя, размер, секретная ссылка. Каждый участник узнаёт только своего получателя. Дедлайн — **5 ноября 2026, 19:19 МСК** (16:19 UTC).

## Размещение: GitHub Pages + Supabase

- GitHub Pages публикует только `index.html` и `config.js`.
- Supabase Edge Function `trusosanta-api` принимает заявки и проверяет секретные ссылки.
- PostgreSQL хранит данные в закрытой схеме `trusosanta_private`. Таблицы и RPC недоступны ролям `anon` и `authenticated`. RPC вызывает только серверная функция с серверным ключом.
- Жеребьёвка атомарна: общая блокировка строки события защищает от одновременных запросов и изменений после дедлайна. Минимум 3 участника, каждый дарит и получает ровно один подарок.
- Секретные ссылки содержат 256-битные случайные ключи в URL-фрагменте. В базе только SHA-256 хеши. Ключи не передаются в URL API, код не журналирует заявки или заголовки.

### Подключение Supabase

1. Создать отдельный проект Supabase либо выбрать подходящий существующий.
2. Применить `supabase/migrations/202610270001_trusosanta.sql` через миграции CLI или SQL Editor. Выполнять один раз; миграция не удаляет данные существующих сторонних таблиц.
3. Установить секрет Edge Function `ALLOWED_ORIGIN=https://naymskim.github.io`.
4. Развернуть `supabase/functions/trusosanta-api/index.ts`, имя функции `trusosanta-api`, **verify_jwt=false**. Пользовательская авторизация реализована секретными ссылками, а не JWT пользователей. Публична только регистрация; чтение и изменения требуют личного ключа.
5. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` доступны только внутри Edge Function. Ни один приватный ключ не должен попадать в `config.js`, HTML или git.
6. Указать в `config.js`: `apiBase: "https://PROJECT_REF.supabase.co/functions/v1/trusosanta-api"`.
7. В GitHub Settings → Pages выбрать **GitHub Actions**, затем запустить workflow **Publish GitHub Pages**.

Для бесплатного аккаунта GitHub Pages обычно требуется публичный репозиторий; Pages для приватного репозитория зависит от плана GitHub. Серверные данные в git не загружаются ни при каком варианте.

### Проверка

```sh
npm ci --ignore-scripts
npm test
python3 -W error::ResourceWarning -m unittest discover -s tests -p 'test_*.py'
```

Тесты Edge Function проверяют CORS, авторизацию, хеширование, ограничение тела запроса и сокрытие внутренних ошибок. SQL исполняется в PGlite (PostgreSQL) для проверки разрешений, регистрации, дедлайна и неизменности жеребьёвки. Python-тесты проверяют локальную реализацию, включая конкурирующие потоки.

## Локальный запуск без Supabase

Оставить `apiBase` пустым и выполнить:

```sh
python3 trusosanta_server.py
```

Открыть http://127.0.0.1:8765. SQLite хранится в `.trusosanta-data/` и исключена из git. Этот режим предназначен для локальной проверки. Для тестов с другой базой: `--data /путь/к/test.sqlite3`.

Двойной щелчок по HTML с пустым `apiBase` включает только локальный предпросмотр формы. Общая регистрация работает через сервер или настроенный Supabase.

## Правила

До дедлайна можно изменить или удалить свою заявку. После дедлайна первое обращение запускает жеребьёвку; открытые страницы обновляются автоматически. При числе участников меньше трёх выводится сообщение об отсутствии жеребьёвки. Результат не перегенерируется.

Секретную ссылку нужно сохранить; автоматического восстановления нет. Один и тот же ключ при повторной отправке не создаёт дублей. Без проверки личности участник может записаться ещё раз с другого устройства. Владелец Supabase технически имеет доступ к базе; общего списка участников в пользовательском интерфейсе нет.

Сайт не использует почту, внешнюю аналитику, рекламные скрипты или сторонние шрифты.
